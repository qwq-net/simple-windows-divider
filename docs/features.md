# 機能

windows-divider は次の 2 つの機能を提供します。設定での名前づけに合わせて、それぞれ機能 A・B と呼びます。

## 介入の原則（いつウィンドウを動かすか）

能動的にウィンドウを動かすのは、矢印ホットキーを押したとき（機能 B・ユーザーの明示操作）だけです。既存ウィンドウのドラッグ・フォーカス移動・表示・最小化解除・新規ウィンドウの生成では動かしません。意図しないタイミングでウィンドウが動くことは大きなストレスになるため、機能を追加・変更するときもこの契機を増やさないことを設計上の不変条件とします。

## 機能 A：標準スナップの無効化

Windows 標準のスナップ（Aero Snap / Snap Assist）を起動時に無効化し、終了時に元へ戻します。レジストリ（HKCU）の現在値を退避してから 0 に書き換え、`SystemParametersInfoW(SPI_SETWINARRANGING)` で実行中のシステムにも反映します。退避内容はファイル（`snap_backup.toml`）にも保存するため、異常終了しても次回起動時に自動で元へ戻せます。`enabled` または `disable_snap` が false の間は退避した設定を復元し、スナップに介入しません。設定は `[general]` の `disable_snap` / `disable_snap_assist` で切り替えます（[configuration.md](configuration.md)）。

## 機能 B：矢印ホットキーによるグリッド配置

各ウィンドウは `columns × rows` のグリッド上で、連続したセル範囲（占有範囲）を持ちます。ホットキーは矢印 4 方向だけで、占有範囲を 1 セルずつ動かします。

| 操作 | 既定キー | 挙動 |
|---|---|---|
| ← / → | `Ctrl+Alt+Left` / `Right` | 列方向。幅 2 列以上は手前の辺を削って寄せ、幅 1 列はその方向へ 1 列広げる。 |
| ↑ / ↓ | `Ctrl+Alt+Up` / `Down` | 行方向。横の占有は保ったまま同様に動かす。 |
| ← と → を同時 | 反対方向を同時押し | 横軸フル（行は維持）。例：`□□□/■□□` → `□□□/■■■`。 |
| ↑ と ↓ を同時 | 反対方向を同時押し | 縦軸フル（列は維持）。横軸フルと縦軸フルの両方で全画面。 |

左右キーの例（3 列・■ が占有）：全幅 →`←`→ `■■□` →`←`→ `■□□` →`→`→ `■■□` →`→`→ `□■□`。

- 四隅・全画面には矢印の組み合わせで到達します（`←` で左端、続けて `↑` で上端＝左上セル。全画面は横軸フル→縦軸フルの 2 ステップ）。専用キーはありません。
- 分割数は `[grid]` の `columns` / `rows` で変えられます（既定はウルトラワイド向けの 3 列 × 2 行）。`auto_aspect` を有効にすると、モニタの解像度アスペクト比から分割数を自動判定します（おおよそ 32:9 → 4×2、21:9 → 3×2、16:9 など → 2×2、縦長 → 1×2）。トレイの「アスペクト比で自動分割」でも切り替えられます。
- 同時押しは待ち時間ゼロで判定します。押した瞬間に反対方向キーが押されているかを `GetAsyncKeyState` で確認するため、単独押しに遅延は乗りません。
- 最大化中のウィンドウに矢印を押すと、いったん通常状態へ戻し、グリッド全体を占有した状態を起点にします。
- 端でこれ以上動けないとき（端セルかつ軸が最小幅）、操作方向に別のモニタがあれば反対側の端セルへ移ります（例：モニタ A の右端セルで `→` → モニタ B の左端セルへ。もう一方の軸の占有は維持）。幅 2 以上のときは同一モニタ内で縮むだけで移動せず、隣が無ければ何も起きません。

配置は、見えるウィンドウの縁がセルにぴったり合うようにします。Windows 10/11 のウィンドウは外周に見えない余白（DWM のリサイズ枠・影領域）を持つため、`DWMWA_EXTENDED_FRAME_BOUNDS` で実寸を測り、その分だけ広げて配置します。操作の起点は、ウィンドウの現在矩形から最も近い格子を推定して決めます（自分の配置はセルに正確に合うため、連続した矢印操作では同じ占有範囲へ戻ります）。

## 動作要件

- Windows 11。スナップ無効化は Windows 11 を対象に調整しています。
- 管理者権限は不要です。非昇格で動かしてください。

## 既知の制約

- UWP / ストアアプリは、実体が `ApplicationFrameHost.exe` 配下のため best-effort です（うまく動かない場合があります）。
- 昇格ウィンドウは、非昇格プロセスからは UIPI で操作できないため触れません（`SetWindowPos` の ACCESS_DENIED はログに残して継続します）。
- タイトルバーもリサイズ枠も持たないウィンドウ（ボーダーレス全画面・オーバーレイ等）は、既定では配置の対象外です。ゲームを避けるための判定で、`skip_non_tileable` で切り替えられます（[anti-cheat.md](anti-cheat.md) / [configuration.md](configuration.md)）。
